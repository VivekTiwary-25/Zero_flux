## How work reaches `cpr-coach`

Workers make their branch from `origin/cpr-coach` in their own folder, push it, and hand back a short note. The boss then, for each task:

1. Reads the diff.
2. Brings the branch up to date with `cpr-coach`, without force-pushing.
3. Runs the gate below.
4. Merges with `--no-ff`, runs the gate again on the merge, and pushes straight away.
5. Adds a line to `docs/TAKEOVER_LOG.md`.

**Merge order: 0, 1, 2, 3, 4, 6, 5.** A later task doesn't wait for an earlier one unless it needs that code. It waits only to merge. If Task 2 is still waiting for the phone at merge time, it's skipped and merges when ready.

## How I prove Practise is unchanged

`cpr-coach/tools/check_practise.ps1` is the gate. It fails if any of these fail:

1. **Protected files:** no change from ee682a1 in PractiseSession, LiveAnalyzer, RateEstimator, PoseEngine, PostureJudge, ElbowGate, LandmarkGuard, PushDetector, SessionMetrics, OneEuroFilter or LoadGovernor.
2. **CoachPolicy:** the five existing settings keep today's default values, and any new settings default to off. Practise builds it with `CoachPolicy()`, so it gets the same values.
3. **Tests not edited:** every test file except the Emergency ones is the same as ee682a1. New test files are fine. `PauseVoiceReplayTest` and `CoachReplayTest` also run Emergency, so any Emergency-only change to them needs a one-line reason in `docs/EMERGENCY_TALK.md` and my own check.
4. **All unit tests pass**, including `RateGoldenTest`, which locks pace counting.
5. **Replay identical:** new `PractiseBaselineTest` runs recordings 10-16 through the real `PractiseSession`. It writes every 250 ms read (tracking, rate, in range, elbows, posture, seconds left), every spoken line with its time, and the scorecard. The output must match byte for byte the files in `tools/testdata/practise_baseline/`, which are made once from ee682a1's code.

**If the replay ever differs after a merge, that merge is reverted** with a new revert commit, and you get a message.
