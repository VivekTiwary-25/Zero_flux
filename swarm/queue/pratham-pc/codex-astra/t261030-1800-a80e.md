Files: engine/PoseEngine.kt, plus PractiseHost.kt only if truly needed. Your own earlier review found this: PoseEngine.close() waits only 500 ms for a frame in submit(), then closes the landmarker anyway, so a slow frame still inside detectAsync can use freed native memory. Fix it so the landmarker is never closed while a submit is in progress, and close() never blocks the main thread for long. For example, if a submit is still running when the wait ends, leave the native close to that submit's finally block, exactly once. Late results must stay harmless. onFrame must never be called after close returns, or the caller must already be safe against that: state which. A failed native close stays caught and logged.
Add JVM-testable logic if you can separate it cleanly, for example a small close-coordination class with a test. Compile with standalone kotlinc if you have no Android SDK, and state exactly what you ran.
