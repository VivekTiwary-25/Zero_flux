# Landmark plausibility study on real CPR recordings (Python)
This is the CPR Coach Android app. Its code is on branch cpr-coach, not in this checkout. Extract a reference copy OUTSIDE this folder:
    git fetch origin cpr-coach
    mkdir -p ../ref-$SWARM_TASK_ID && git archive FETCH_HEAD cpr-coach | tar -x -C ../ref-$SWARM_TASK_ID
Recordings: ../ref-<id>/cpr-coach/tools/testdata/real-cph2467-*.csv (labels in labels.csv there). Columns: t_ms, wrist_signal, elbow_deg, min_vis, ..., side, shoulder_x, shoulder_y, elbow_x, elbow_y, wrist_x, wrist_y, hip_x, hip_y, *_vis, side_on, world_*. Coordinates are normalised to a 4:3 landscape image: multiply x by 4/3 before any geometry.

Files to create in THIS checkout: `cpr-coach/tools/guard_study.py` and `cpr-coach/docs/GUARD_STUDY.md` only.

Known failure (recording 15, 54-61.5 s, labelled bent from pictures): MediaPipe's wrist alternates frame-to-frame between the real hand (forward of the elbow) and a phantom directly below the elbow, in runs up to ~300 ms; forearm length is the same in both. The app will reject implausible frames. Your job is an INDEPENDENT check of candidate rules, so the app's Kotlin version can be compared against it.

Implement in guard_study.py, positions relative to the hip and in torso lengths (|shoulder-hip|), compared with the LAST ACCEPTED frame:
- horizontal wrist/elbow jump limit L (sweep 0.10..0.35),
- bone-length ratio window vs a 2 s median of accepted frames (sweep),
- wrist behind the shoulder on the hips' side, or above the shoulder,
- re-anchor after R ms of continuous rejection when the rejected frames agree (sweep 250..500 ms),
- side column change resets the reference.
For each setting report per recording 1-15: rejected share, longest rejected run (ms), and for recording 15 per labelled segment: rejected share and the median 2D elbow angle of accepted frames (elbow angle at the elbow from shoulder/elbow/wrist, x scaled by 4/3). Also the 1 s rolling median of the signed offset (wx-sx)*dir/armLength, dir = +1 if wrist x >= hip x else -1, per labelled segment.
Goal of a good setting: straight segments rejected < 5%, longest run < 450 ms everywhere, and in 15 the accepted bent frames read clearly below the straight ones.
Write GUARD_STUDY.md: the method, a table of the best 3 settings, and the per-segment numbers for the best one. Plain, short sentences. Python 3 stdlib only. Include the command you ran.
