See lab/LabAudioService.kt for the working click sound and AudioTrack setup. One background thread owns one streaming AudioTrack at 48 kHz mono 16-bit. It writes short blocks (about 10 ms) of a mix of the click and any playing clip, computed by counting samples, so the beat is sample-exact and never uses a timer or Handler. Mix with clipping protection (saturate, do not wrap). If a new clip is requested during another, the new one replaces it. onDone is posted to the main thread.
WavClip: parse a PCM 16-bit mono RIFF WAV from bytes, skip unknown chunks, and resample to 48 kHz by linear interpolation (voices are 16 kHz or 22.05 kHz). Reject non-PCM or non-16-bit with a clear exception. Keep it free of Android imports so it can be tested on the JVM.
WavClipTest with JUnit 4: header parsing including an extra chunk, resampled length, rejection of bad formats.
Done when the class exists with exactly this API and the JVM test passes if you are able to run it.
