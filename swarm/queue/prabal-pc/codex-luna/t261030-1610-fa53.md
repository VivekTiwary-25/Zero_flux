# Trace analysis tool for measuring real accuracy
This is the CPR Coach Android app (Kotlin, Jetpack Compose). Its code is on branch cpr-coach, not in this checkout. To read it, without changing branch, extract a reference copy OUTSIDE this folder:
    git fetch origin cpr-coach
    mkdir -p ../ref-$SWARM_TASK_ID && git archive FETCH_HEAD cpr-coach | tar -x -C ../ref-$SWARM_TASK_ID
(On Windows PowerShell use $env:SWARM_TASK_ID.) Read ../ref-<id>/cpr-coach/docs/SPEC.md (sections 1, 3 and 5 are the product and design rules), plus ui/Theme.kt and ui/Contract.kt under app/src/main/java/com/zeroflux/cprcoach/. Use their colours, ClayButton, GlassPanel, AppLanguage, MicState, CameraUiState and LocalStrings. Do not change those files or copy them here.
Only create the NEW files listed below, at those paths under cpr-coach/ in this folder. Nothing else may appear in this folder. Files written by other workers are referenced by the signatures given here, so do not write them yourself.
All visible text goes through LocalStrings.current.get("key") using keys in assets/strings/en.json. If you need a new key, do not edit en.json: list the key and its English in your report.
No invented numbers anywhere: no sample rates, scores or demo values in production code.
You do not need to compile if this machine has no Android SDK, and do not install one. Be careful with imports, because the boss compiles and reviews afterwards. Say in your report whether you compiled.

New files: cpr-coach/tools/analyze_trace.py and cpr-coach/docs/MEASUREMENTS.md. Python 3.12, standard library plus numpy only.
The app saves session CSVs with header t_ms,wrist_signal,elbow_deg,min_vis,latency_ms. Rows with no person have empty signal values. A lab screen saves another format, with header t_ms,side,sh_x,sh_y,sh_v,el_x,el_y,el_v,wr_x,wr_y,wr_v,hip_x,hip_y,hip_v,elbow_deg,wrist_signal,latency_ms,delegate. Read both.
Usage: python analyze_trace.py <csv> [--count N --seconds S]. Prints: duration, frames per second (median and 5th percentile), median and 95th percentile latency, share of frames with min visibility at least 0.5, elbow angle median and range, and the compression rate from the signal in sliding 6 second windows (same idea as engine/RateEstimator.kt: resample to 30 Hz, remove a 1 second moving average, normalised autocorrelation over 60 to 170 per minute, shortest lag at least 0.6 of the best), printing median rate. With --count and --seconds it also prints the human-counted rate and the difference. Print "no usable beat" when there is none, and never guess. Test it on a CSV you synthesise, and do not commit that file.
MEASUREMENTS.md: an empty results table only (date, phone, run, human count, seconds, human rate, app rate, difference, fps, latency) plus how to pull traces with adb from the app's external files folder under traces/. It must contain no results, since nothing has been measured yet.
