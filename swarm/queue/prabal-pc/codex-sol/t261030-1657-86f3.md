# Fix reviewed defects in the metronome service and mic
This is the CPR Coach Android app (Kotlin, Jetpack Compose). Its code is on branch cpr-coach, not in this checkout. To read it, without changing branch, extract a reference copy OUTSIDE this folder:

You are editing EXISTING files, which is an exception to "only new files". Copy each named file from your reference copy to the same path here and edit it there. Keep public signatures. Change no others. Small safe changes only: a build goes on a phone tonight.

Files: audio/MetronomeService.kt, voice/HandsFreeController.kt, voice/SpeechRecognizerManager.kt. Check each defect against the current code first, because some were reported against an older copy, and say which were already fine.
1. MetronomeService: stop() then an immediate start(): the old instance's onDestroy releases and nulls the new session's engine. An instance must only release the engine it created, and a fast restart must leave a working metronome. Keep USAGE_VOICE_COMMUNICATION: real phone testing chose it, because media audio stops during a call.
2. MetronomeService: stop arriving before onStartCommand must not cause ForegroundServiceDidNotStartInTimeException. A blank or null language falls back to "en".
3. HandsFreeController: a phrase whose transcription finishes after the silence timeout has its onTranscript dropped, so the user's "start" is lost. Let the pending segments finish before going OFF, within a short bound of about 3 seconds, without keeping the mic open.
4. SpeechRecognizerManager: release() while a decode or a model load is running on another thread can use freed native memory or leak the model. Serialise them with one lock, and make release wait for the decode. Must not block the main thread for long: if needed run the native release on a background thread.
