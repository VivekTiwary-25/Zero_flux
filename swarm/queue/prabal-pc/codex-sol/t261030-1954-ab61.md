What we know: tools/testdata/real-rmx3392-1.csv has wrist_signal (wrist height above hip, in torso lengths) with window RMS of only about 0.03, weak correlation (at best 0.42), frame gaps up to 0.46 s, and elbow median about 100 degrees where straight arms should read 170 or so. Read docs/REAL_TRACE_1.md. On a soft cushion the hands may move little relative to the hip, while the shoulders may move more, so the wrist signal may be the wrong one. The recording can't answer this, as it has no shoulder column. A new recording will have columns after the existing ones: side,shoulder_x,shoulder_y,elbow_x,elbow_y,wrist_x,wrist_y,hip_x,hip_y,shoulder_vis,elbow_vis,wrist_vis,hip_vis.
The tool: python compare_signals.py <csv> [--count N --seconds S]. For candidates wrist minus hip, shoulder minus hip, shoulder alone, wrist alone, and elbow angle, print per 6 second window: frames a second, largest gap, RMS, best rate 60 to 170 a minute, correlation strength, and whether that window has any gap over half the detected period. Then a summary per candidate: share of windows with a confident beat, median rate, and error against the human count if given. Must work with the old file too, using only the columns present and saying which candidates it could not compute. Test it on the real file and on a synthetic file you make outside this folder, and do not commit that file.
RATE_NEXT_STEPS.md: under one page. What the next recording will let us decide, with the rule for choosing a signal, written before seeing the data so we can't fool ourselves. Say plainly what is known and what isn't. No results beyond what your run produced. Do not touch any phone.
