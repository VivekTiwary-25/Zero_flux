# Screen text loader and voice command matcher
This is the CPR Coach Android app (Kotlin, Jetpack Compose). Its code is on branch cpr-coach, not in this checkout. To read it, without changing branch, extract a reference copy OUTSIDE this folder:

New files: cpr-coach/app/src/main/java/com/zeroflux/cprcoach/ui/AssetStrings.kt, .../voice/CommandMatcher.kt and cpr-coach/app/src/test/java/com/zeroflux/cprcoach/voice/CommandMatcherTest.kt

AssetStrings, package com.zeroflux.cprcoach.ui:
    class AssetStrings private constructor(...) : Strings { companion object { fun load(context: Context, code: String): AssetStrings } }
Loads assets/strings/<code>.json over assets/strings/en.json, so a missing key or file falls back to English and then to the key itself, never crashing. Use org.json.

CommandMatcher, package com.zeroflux.cprcoach.voice, pure Kotlin with no Android imports:
    enum class VoiceCommand { EMERGENCY, PRACTISE, START, STOP, REPEAT, CALL }
    sealed interface MatchResult { data class Command(val command: VoiceCommand) : MatchResult; data class Language(val code: String) : MatchResult; data object None : MatchResult }
    class CommandMatcher(table: Map<String, CommandTable>) { fun match(transcript: String, languageCode: String, allowed: Set<VoiceCommand>, allowLanguages: Boolean): MatchResult }
    data class CommandTable(val commands: Map<VoiceCommand, List<String>>, val languages: Map<String, List<String>>)
Also fun parseCommandTable(json: String): Map<String, CommandTable> in the same file using a small hand-written approach is NOT wanted: keep the JSON parsing in AssetStrings.kt as fun loadCommandTable(context: Context): Map<String, CommandTable> using org.json. The file assets/commands.json has the shape { "<code>": { "emergency": [...], "practise": [...], "start": [...], "stop": [...], "repeat": [...], "call": [...], "languages": { "<code>": [...] } } }.
Matching: lower-case and trim the transcript, strip punctuation including the danda, and match whole words or whole phrases only, so "restart" does not match "start". Only commands in allowed may match. If two different commands match, return None rather than guess, because a wrong command is worse than no command.
Tests with JUnit 4: whole-word rule, allowed filter, ambiguity gives None, Kannada-script input, language match, unknown language code gives None.
