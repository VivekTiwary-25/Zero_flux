# Independent review of LandmarkGuard (ghost wrist rejection) and the overlay hold
This is the CPR Coach Android app (Kotlin, Compose). Its code is on branch cpr-coach, not in this checkout. Extract a reference copy OUTSIDE this folder without changing branch:
    git fetch origin cpr-coach
    mkdir -p ../ref-$SWARM_TASK_ID && git archive FETCH_HEAD cpr-coach | tar -x -C ../ref-$SWARM_TASK_ID
(PowerShell: $env:SWARM_TASK_ID.) Unit tests: inside ../ref-<id>/cpr-coach run gradlew.bat testDebugUnitTest (set sdk.dir in local.properties if Gradle asks).

Deliverable: cpr-coach/docs/REVIEW_LANDMARK_GUARD.md only. Do not edit app code.

Commit c578e2f added engine/LandmarkGuard.kt (rejects frames whose wrist/elbow jump, drift from a 1.5 s median, change bone length, or cross behind the shoulder; re-anchors after 350-400 ms), drops rejected frames in LiveAnalyzer.addFrame(PoseFrame), and makes PractiseHost's overlay show the last accepted arm instead of a rejected one (overlayGuard.overlayFrame). Read `git show c578e2f` and LandmarkGuardTest.kt.
Review for real bugs only:
- Can the guard lock onto a phantom and reject the real arm for a long time? Can it cause tracking LOST flicker on a real phone at 15-30 fps (frame gaps 30-70 ms; the load governor can stretch gaps)?
- Thread safety: which threads call overlayFrame and LiveAnalyzer.addFrame (MediaPipe result thread vs main thread)? Is any guard instance shared across threads?
- Side switch, session restart, pause/resume (PractiseSession.togglePause makes a new LiveAnalyzer), EmergencyHost (uses LiveAnalyzer but its overlay was not changed: does its skeleton still show phantom points?).
- Units: aspect scaling, torso length near zero, NaN/infinite inputs.
For each finding: code path, a concrete frame sequence that fails, and a suggested fix. If you can, add the failing case as a JUnit test code block in the doc and run it in the ref copy to confirm. Say clearly if you find nothing serious.
