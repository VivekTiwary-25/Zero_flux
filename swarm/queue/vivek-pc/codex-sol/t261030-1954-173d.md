# Run at the best frame rate the phone can handle

You are editing EXISTING files, which is an exception to "only new files". Copy each named file from your reference copy to the same path here and edit it there. Keep public signatures unless told otherwise. Change no others. Do not touch any phone or emulator: run no adb at all.

Files: engine/LoadGovernor.kt and its test, engine/PoseEngine.kt, ui/PoseCameraView.kt, and app/src/debug/.../PractiseReplay.kt only if the trace format needs it.
Facts measured on real phones: results came at about 8.5 a second on both an RMX3392 and a CPH2467, with pose latency only about 60 ms, so the phones have capacity to spare. Both report thermal status 3 even when idle, with normal battery temperature (33 to 35 C), which forces LoadGovernor's lowest step. In an earlier test outdoors the same RMX reached 26 frames a second at 73 ms. The real session with gaps up to 0.46 s could not resolve a 0.55 s compression cycle.
1. Thermal status alone must not force a slower step while battery temperature is normal. Treat heat as real only when battery temperature is at or above a named constant of 40 C, or the status is CRITICAL or above. If the temperature is unknown (NaN), use latency only. Keep stepping down on sustained high latency.
2. Add a faster top step, so the steps give about 25, 15 and 10 frames a second on a 30 fps camera. Start at the top. Remember a gap really waits for the next camera frame, and keep the existing test that every step stays at or above 10 a second, adding a test that the top step is at or above 24. Also keep this safe: heat must still step it down.
3. Camera frame supply: in low light the camera may drop to 15 frames a second or lower. Ask CameraX for a target frame rate range of about 24 to 30 for the analysis and preview (Preview.Builder.setTargetFrameRate and the equivalent for ImageAnalysis if the API offers it, else Camera2Interop). Confirm the API exists in the camerax version in libs.versions.toml by compiling. If the camera refuses a range, it must not crash: fall back to the default and log under CPR_CAM.
4. Record what we need to understand real motion. Append columns AFTER the current ones in the trace CSV: side (L or R), shoulder_x, shoulder_y, elbow_x, elbow_y, wrist_x, wrist_y, hip_x, hip_y, shoulder_vis, elbow_vis, wrist_vis, hip_vis, in image-normalised coordinates, written as the near arm chosen for that frame. Check the replay reader and tools/analyze_trace.py still read longer rows. Keep the flush behaviour.
5. Include in the stats line the real camera frames per second arriving, before any skipping, and the actual analysis frame size, so a low camera rate can be told apart from our own cap.
Do not change the pose model or RateEstimator. Add JVM tests for 1 and 2.
This PC has the Android SDK at %LOCALAPPDATA%\Android\Sdk. You must compile and test: gradlew assembleDebug testDebugUnitTest in your reference copy, with sdk.dir in local.properties (forward slashes). The Whisper assets are not needed for this build.
