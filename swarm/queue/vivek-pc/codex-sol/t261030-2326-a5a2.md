# Live overlay: controls must never move, for any language
This is the CPR Coach Android app (Kotlin, Jetpack Compose). Its code is on branch cpr-coach, not in this checkout. To read it, without changing branch, extract a reference copy OUTSIDE this folder:
    git fetch origin cpr-coach
    mkdir -p ../ref-$SWARM_TASK_ID && git archive FETCH_HEAD cpr-coach | tar -x -C ../ref-$SWARM_TASK_ID
(On Windows PowerShell use $env:SWARM_TASK_ID.) Read ../ref-<id>/cpr-coach/docs/SPEC.md (sections 1, 3 and 5 are the product and design rules), plus ui/Theme.kt and ui/Contract.kt under app/src/main/java/com/zeroflux/cprcoach/. Use their colours, ClayButton, GlassPanel, AppLanguage, MicState, CameraUiState and LocalStrings. Do not change those files or copy them here.
Only create the NEW files listed below, at those paths under cpr-coach/ in this folder. Nothing else may appear in this folder. Files written by other workers are referenced by the signatures given here, so do not write them yourself.
All visible text goes through LocalStrings.current.get("key") using keys in assets/strings/en.json. If you need a new key, do not edit en.json: list the key and its English in your report.
No invented numbers anywhere: no sample rates, scores or demo values in production code.
You do not need to compile if this machine has no Android SDK, and do not install one. Be careful with imports, because the boss compiles and reviews afterwards. Say in your report whether you compiled.
You are editing an EXISTING file, an exception to "only new files": copy ui/CameraOverlay.kt from your reference copy to the same path here and edit LiveOverlay only. Change nothing else. Run no adb and touch no phone or emulator.
A first attempt at this was rejected, for these reasons, so avoid them:
1. A bottom Row with no fixed height, vertically centred, with buttons at heightIn(min = 56.dp) whose text can wrap. A two-line elbow label makes the Row grow and moves the buttons, and Pause and Resume can differ in height. Give the bottom band a fixed height, and give each control a fixed position and size, so that nothing in it can change their place. Long labels shrink or wrap inside that fixed space and never clip. Buttons stay at least 56 dp tall.
2. Choosing a compact rate font from the height of the top region, which shrinks when the bottom changes, so the rate jumps size when a label appears. Decide the rate font from the whole screen height only, once.
3. The no-rate text has maxLines = 1 at 88 to 104 sp with no shrink, so a long translation clips. It must shrink to fit.
Keep the spec's rule that the rate is the biggest thing on screen, keep colours unchanged, and don't add per-frame subcomposition. Test the longest labels by reasoning about Malayalam live_pause and live_stop at 640x360 dp and font scale 1.3, and say what you checked.
This PC has the Android SDK at %LOCALAPPDATA%\Android\Sdk. You must compile and test: gradlew assembleDebug testDebugUnitTest in your reference copy, with sdk.dir in local.properties (forward slashes).
