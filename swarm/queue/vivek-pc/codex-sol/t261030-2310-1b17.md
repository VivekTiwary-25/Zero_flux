File: audio/AudioEngine.kt, plus a JVM test if the logic can be pulled into a small pure helper. A review reported the following; check each against the code and say which are real.
1. runLoop: `playbackTrack = openTrack() ?: break` leaves the loop on the first failed reopen instead of retrying up to the limit.
2. After more than 20 failed attempts, about 6 s, the loop ends and playback is abandoned for good. A phone call can last far longer. Emergency keeps saying compressing, so the metronome must keep trying for as long as the engine is not released, at a calm retry interval and without spinning or filling the log.
3. A reopened stream track can accept its first block then fail on a later one, resetting the attempt counter. Count success only after the track has stayed alive for a while.
4. render(block) advances the beat and clip position and fires clipDone before the write succeeds, so audio can be lost silently during a failure.
5. After Thread.sleep the loop doesn't check released before opening a track, so a track can be opened after release(), which would be a leak. Also make sure a sleeping loop can't delay release.
Keep the single mixed track, exact beat timing and the existing voice mute.
