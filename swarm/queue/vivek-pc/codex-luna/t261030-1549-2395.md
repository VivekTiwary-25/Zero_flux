# Write the clip generator and generate the voice clips
This is the CPR Coach Android app (Kotlin, Jetpack Compose). Its code is on branch cpr-coach, not in this checkout. To read it, without changing branch, extract a reference copy OUTSIDE this folder:
    git fetch origin cpr-coach
    mkdir -p ../ref-$SWARM_TASK_ID && git archive FETCH_HEAD cpr-coach | tar -x -C ../ref-$SWARM_TASK_ID
(On Windows PowerShell use $env:SWARM_TASK_ID.) Read ../ref-<id>/cpr-coach/docs/SPEC.md (sections 1, 3 and 5 are the product and design rules), plus ui/Theme.kt and ui/Contract.kt under app/src/main/java/com/zeroflux/cprcoach/. Use their colours, ClayButton, GlassPanel, AppLanguage, MicState, CameraUiState and LocalStrings. Do not change those files or copy them here.
Only create the NEW files listed below, at those paths under cpr-coach/ in this folder. Nothing else may appear in this folder. Files written by other workers are referenced by the signatures given here, so do not write them yourself.
All visible text goes through LocalStrings.current.get("key") using keys in assets/strings/en.json. If you need a new key, do not edit en.json: list the key and its English in your report.
No invented numbers anywhere: no sample rates, scores or demo values in production code.
Be careful with imports, because the boss compiles and reviews afterwards. Say in your report whether you compiled.
A full build must be on a phone tonight, so prefer the simple working version and stop when it meets the brief.

This PC has the voice models in D:\projects\sih\iTantra\app\src\main\assets. Read that folder only, never change anything in D:\projects\sih\iTantra. Python 3.12 with the sherpa_onnx package is installed.
New files: cpr-coach/tools/clipgen/generate_clips.py, cpr-coach/tools/clipgen/README.md, and generated cpr-coach/app/src/main/assets/clips/<code>/<key>.wav with manifest.json, plus cpr-coach/docs/CLIP_STATUS.md.

Usage: python generate_clips.py --models <folder holding the voice folders> --out <assets/clips> [--lang en,hi] [--dry-run]
Phrase files are on the branch at cpr-coach/tools/clipgen/phrases_<code>.json, flat key to text. The script reads them from beside itself, so during your run copy them next to the script temporarily, and do NOT include copies of them in this folder at the end.
It writes <out>/<code>/<key>.wav, PCM 16-bit mono, and a manifest of code, key, text and sha256 of the text. Print a summary and exit non-zero if any clip failed, continuing through the others.
Voices, all VITS through sherpa_onnx.OfflineTts:
- Piper, which uses tokens.txt and espeak-ng-data as data_dir: en = vits-piper-en_US-ryan-medium/en_US-ryan-medium.onnx, hi = vits-piper-hi_IN-pratham-medium/hi_IN-pratham-medium.onnx, ml = vits-piper-ml_IN-arjun-medium/ml_IN-arjun-medium.onnx
- Meta MMS, which uses model.onnx and tokens.txt with no espeak data: bn = vits-mms-ben, or = vits-mms-ory, gu = vits-mms-guj, mr = vits-mms-mar, te = vits-mms-tel, kn = vits-mms-kan, ta = vits-mms-tam
MMS has a plain character frontend: read tokens.txt and drop characters not in it (such as stray punctuation) before synthesis, and report what was dropped per phrase. Fail a clip that contains digits. Trim silence at both ends and normalise peak to about -3 dBFS so all voices match. Use the sample rate the model reports.

Generate en and hi first. Those two are required. Then kn, then the other seven if they work. Ask for no human help: if a language fails, record it and carry on.
Check each WAV: it parses, is mono 16-bit, and lasts between 0.2 and 8 seconds. Put the duration table in your report.
CLIP_STATUS.md: a table of language, key, text, "generated yes/no" and "checked by a person" set to NO for everything. Nobody has listened to these, so never mark any as checked.

This PC has the Android SDK at %LOCALAPPDATA%\Android\Sdk. To compile: copy your new files into the reference copy, add a local.properties there with sdk.dir pointing at it (forward slashes), and run gradlew compileDebugKotlin there. Keep all such copies outside this folder.
