# Independent review of the personal-baseline posture judge
This is the CPR Coach Android app (Kotlin). Its code is on branch cpr-coach, not in this checkout. Extract a reference copy OUTSIDE this folder:
    git fetch origin cpr-coach
    mkdir -p ../ref-$SWARM_TASK_ID && git archive FETCH_HEAD cpr-coach | tar -x -C ../ref-$SWARM_TASK_ID
Unit tests: in ../ref-<id>/cpr-coach run gradlew.bat testDebugUnitTest (set sdk.dir in local.properties if needed).

Deliverable in THIS checkout: cpr-coach/docs/REVIEW_POSTURE_BASELINE.md only. Do not edit app code.

Commit f99a1bc (`git show f99a1bc` after the fetch) makes engine/PostureJudge.kt learn a per-session baseline from the first ~6 s of judged side-on frames whose 1 s elbow median is >= 160: bent = median below (baselineElbow - 28) clamped to [145,158], straight from +8; lean = |offset - baselineOffset| > 0.19 or |offset| > 0.45, 0.04 hysteresis. reset() keeps the baseline; a new LiveAnalyzer starts fresh (PractiseSession makes a new one on resume after a user pause).
Review for real problems only, each with a concrete frame/reading sequence:
- A baseline formed while the rescuer is actually leaning or mildly bent (e.g. 160-165 deg arms during the first 6 s): what is then missed or falsely flagged?
- Pause/resume: does the user's pause button (new LiveAnalyzer) throw the baseline away, so the next 6 s can't flag mild bends? Is that acceptable or should the baseline live in PractiseSession?
- Rescuer swap or camera moved mid-session: stale baseline effects.
- EmergencyHost: same judge, no straight start guaranteed.
- Numeric edge cases: NaN, side-on flicker, offset sign flips when the wrist crosses the hip x.
Write any failing case as a JUnit test code block and run it in the ref copy. Rank by how likely it shows up in a 2-minute demo. Say clearly if nothing serious.
